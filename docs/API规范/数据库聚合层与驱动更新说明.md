# YZF 数据库聚合层更新说明

## 版本摘要

本次更新将数据库访问统一到 `YZFDatabaseRegistry`，并增加 `YZFAggregatedDatabase` 异步聚合层。SQLite 与本地 JSON 保持内置，其余 JDBC 数据库通过 `drivers/` 外部驱动启用，因此可以在不修改服务端核心包的情况下替换或增加驱动。

## 支持的数据库

| 数据库 | 类型 | 驱动 | 适用场景 | 高可用模式 |
|---|---|---|---|---|
| Local JSON | `local` | 内置 | 配置、轻量 KV、离线部署 | 单机、原子写入 |
| SQLite | `sqlite` | 内置 JDBC | 默认玩家存储、单机 | 单节点 |
| MySQL | `mysql` | 外置 | 通用生产环境 | standalone、replication、loadbalance |
| MariaDB | `mariadb` | 外置 | MySQL 兼容生产环境 | standalone、replication、loadbalance |
| PostgreSQL | `postgresql` / `postgres` | 外置 | 强一致、复杂查询 | standalone、replication、loadbalance |
| Microsoft SQL Server | `sqlserver` / `mssql` | 外置 | Windows/企业 SQL Server | standalone、replication、loadbalance |
| Remote JSON | `remote` | HTTP 外部服务 | 跨进程或跨主机存储 | 由 HTTP 服务负责 |

Redis 与 MinIO 属于外部服务连接器，不是 KV 数据库主存储；它们仍可与上述数据库同时启用。

## 外部驱动安装

执行 `gradlew.bat server:yzfDriverBundles`，然后将 `server/build/yzf-driver-bundles/` 下需要的目录复制到运行目录的 `drivers/`：

```text
drivers/
├─ mysql-default/
├─ mariadb-default/
├─ postgresql-default/
└─ sqlserver-default/
```

`config/yzf/data/driver-index.hjson` 中的 `path`、`driverClassName` 和 `serviceTypes` 必须与目录一致。驱动缺失时服务不会阻塞启动，访问该数据库时会报告不可用并允许后续重试。

## 服务配置示例

```hjson
{
  id: "player-sqlserver"
  type: "sqlserver"
  enabled: true
  driverId: "sqlserver-default"
  endpoint: "127.0.0.1:1433"
  database: "mindustry_player"
  username: "sa"
  password: "change-me"
  clusterMode: "standalone"
  options: ["encrypt=false", "trustServerCertificate=true"]
}
```

多节点配置：

```hjson
{
  id: "player-postgresql-ha"
  type: "postgresql"
  driverId: "postgresql-default"
  database: "mindustry_player"
  username: "mindustry"
  password: "change-me"
  clusterMode: "loadbalance"
  nodes: ["db-1:5432", "db-2:5432", "db-3:5432"]
}
```

可用模式：`standalone` 单节点、`replication` 主从节点池、`loadbalance` 轮询和故障切换、`cluster` 集群节点池、`sentinel` 哨兵拓扑配置。节点健康检查使用连接池连接验证，失败节点会自动跳过。

## 聚合调用

```java
try(YZFAggregatedDatabase db = registry.aggregate(
    "local", "service-player-sqlite", "service-player-postgresql")){
    db.get("player", "123").thenAccept(json -> {
        // 首个返回的非空结果作为读取结果
    });
    db.set("player", "123", json).thenAccept(result -> {
        // result.targets() 为目标数，result.failures() 为失败数
    });
}
```

读取会并行请求所有目标并采用首个非空结果；写入会并行广播到所有目标并返回失败统计。数据库操作运行在线程池，不占用 Mindustry 游戏事件线程。

## 数据一致性与性能优化

- SQL KV 表使用 `(category, entry_key)` 主键和数据库原生 upsert/merge。
- JSON 导入使用事务，失败自动回滚。
- HikariCP 为每个节点维护独立连接池，并复用连接。
- 本地 JSON 使用临时文件和原子替换，避免进程中断产生半文件。
- 聚合写入适合双写、迁移和灾备；需要强一致时应只配置一个主写库。
- SQLite 适合单机轻量负载，不建议作为多实例共享存储。
