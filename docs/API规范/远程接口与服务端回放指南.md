# 远程接口、认证与服务端回放指南

本文描述当前 YZF 服务端实际提供的网络能力、插件调用方法，以及不依赖客户端画面的服务端回放记录方案。

## 1. 网络能力总览

| 能力 | 方向 | 用途 | 核心是否自带入站监听器 |
|---|---|---|---|
| 命令 socket | 外部 → 服务端 | 发送控制台命令、远程运维 | 是，默认 `localhost:6859`，需开启 `socketInput` |
| HTTP/HTTPS | 服务端 → 远端 | 调用已配置的 HTTP 服务 | 否 |
| Remote JSON Database | 服务端 → 远端 | 远程键值/JSON 数据库存取 | 否 |
| WebSocket | 服务端 → 远端 | 长连接、消息推送、远程桥接 | 否 |
| Web UI 页面注册 | 插件 → WEB 插件 | 提供页面描述 | 否；实际 HTTP 由 WEB 插件实现 |

**重要：** 核心服务端目前没有通用入站 HTTP/HTTPS API。因此不能把 `yzf.remote` 或 `yzf.ws` 当作 Web 服务器接口；它们均由服务端主动连接远端。

## 2. 外部访问安全配置

文件：`config/yzf/config/external-access.hjson`

```hjson
enabled: true
requireTokenForPublic: true
requireTokenForPrivate: false
attachTokenToOutbound: true
requireTlsForPublic: true
token: ""
tokenFile: "config/secrets/external-access.token"
passwordFile: ""
secretFile: ""
keyFile: ""
```

### 2.1 字段与优先级

Token 来源优先级：`secretFile/keyFile` > `passwordFile` > `tokenFile` > `token`。

| 字段 | 行为 |
|---|---|
| `enabled` | 关闭后不执行外部访问策略；生产环境应保持开启。 |
| `requireTokenForPublic` | 非私网目标或客户端必须认证。 |
| `requireTokenForPrivate` | 回环、局域网、链路本地地址也需要认证。 |
| `attachTokenToOutbound` | 对框架发起的 HTTP/WS 加 `Authorization: Bearer <token>`。 |
| `requireTlsForPublic` | 公网仅允许 `https://`、`wss://`。 |
| `token` | 直接 Token，最少 128 字符。 |
| `tokenFile` / `passwordFile` | UTF-8 文本文件，内容作为 Token。 |
| `secretFile` / `keyFile` | 任意二进制文件；服务端计算 SHA-512，令牌格式为 `sha512:<base64url摘要>`。 |

所有文件路径相对 `config/yzf` 根目录，不需要写机器绝对路径。

### 2.2 证书与私钥

公开证书不是秘密，不能作为 Token。私钥或私有图片可作为 `secretFile` 素材，但必须限制文件权限。当前核心没有入站 HTTPS 监听器；证书、私钥、mTLS 只能在以后新增的 HTTPS API 中通过 KeyStore/PKCS#12 正确配置。

## 3. 命令 socket

### 3.1 开启

在服务端配置中启用 `socketInput`，默认绑定 `localhost:6859`。若绑定到公网地址，必须保持 `requireTokenForPublic: true` 且配置有效 Token。

### 3.2 协议

采用 UTF-8、每行一条文本命令。

公网或要求认证的内网连接，第一行必须是：

```text
AUTH <token>
```

成功后可发送：

```text
status
help
yzf help
```

认证失败响应：

```text
ERR authentication required
```

Socket 会广播服务端日志。客户端必须持续读取输出，避免本地缓冲区堵塞。多个客户端可并发连接；任一客户端断开不会阻塞其他客户端。

### 3.3 插件与 socket 命令

插件不直接占用 socket 端口，而是注册服务端命令，由 socket 命令触发：

```javascript
yzf.command("record-status", "显示回放记录状态", function(args){
  yzf.info("recorder is running");
});
```

远端认证由核心在命令进入插件前完成；插件回调无需自行解析 `AUTH`。

## 4. 外发 HTTP/HTTPS

先在 `config/services/` 中创建一个 `type: "http"` 的服务，填写 `id`、`endpoint`、超时和节点。插件通过服务 ID 调用，不直接管理端口。

```javascript
var response = yzf.remote.get("telemetry", "/v1/status");
var result = yzf.remote.postJson("telemetry", "/v1/events", JSON.stringify({
  kind: "game-start",
  time: Date.now()
}));
```

| API | 作用 |
|---|---|
| `yzf.remote.get(serviceId, path)` | 对已配置 HTTP 服务执行 GET。 |
| `yzf.remote.postJson(serviceId, path, body)` | 以 JSON 执行 POST。 |
| `yzf.service.has(id)` | 判断服务是否已加载。 |
| `yzf.service.summary(id)` | 获取服务摘要。 |
| `yzf.service.list()` / `info(id)` | 查询服务配置和状态。 |

公网目标受 `external-access.hjson` 控制：默认必须 HTTPS、必须有 Token，并自动带 Bearer 请求头。远端 HTTP 服务应验证该请求头；示例伪代码：

```text
if Authorization != "Bearer <expected-token>": return 401
else: process request
```

HTTP 请求是短连接，不存在“释放远程端口”的操作；请求完成后连接由 HTTP 客户端关闭或复用。

## 5. 远程 JSON 数据库 API

远程 JSON 数据库通过数据库定义的 `endpoint` 访问，接口约定如下：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/categories` | 分类列表 |
| GET | `/categories/{category}/keys` | 键列表 |
| GET | `/categories/{category}/keys/{key}` | 读取值 |
| POST | `/categories/{category}/keys/{key}` | 写入 JSON 值 |
| DELETE | `/categories/{category}/keys/{key}` | 删除值 |
| GET | `/dump` | 导出全部数据 |
| POST | `/import` | 导入全部数据 |

插件 API：

```javascript
yzf.db.set("remote-main", "replay", "session-1", {state: "running"});
var item = yzf.db.get("remote-main", "replay", "session-1", null);
```

该连接同样自动遵守 HTTPS 与 Bearer Token 策略。远端实现必须验证 Authorization，并限制可读写的分类和键。

## 6. 外发 WebSocket

```javascript
var connectionId = yzf.ws.connect(
  "wss://example.invalid/bridge",
  function(id){
    // TCP/TLS/WS 握手完成；认证头已由核心自动附加。
    yzf.ws.send(id, JSON.stringify({type: "subscribe", topic: "server-events"}));
  },
  function(id, message){
    var packet = JSON.parse(message);
    // 仅处理协议白名单内的远端消息。
  },
  function(id, code, reason){
    yzf.info("remote websocket closed: " + code);
  },
  function(message){
    yzf.err("remote websocket failed: " + message);
  }
);
```

| API | 作用 |
|---|---|
| `yzf.ws.connect(url, onOpen, onMessage, onClose, onError)` | 异步创建连接，立即返回连接 ID。 |
| `yzf.ws.send(id, text)` | 发送 UTF-8 文本。连接尚未完成时返回 `false`。 |
| `yzf.ws.sendBinary(id, base64)` | 发送 Base64 解码后的二进制数据。 |
| `yzf.ws.isOpen(id)` | 查询是否已完成连接。 |
| `yzf.ws.close(id)` | 主动释放远端 WebSocket。模块卸载时框架也会清理。 |
| `yzf.ws.list()` | 返回连接 ID、URL 与打开状态。 |

远端 WebSocket 服务应同时校验 HTTP Upgrade 请求的 `Authorization: Bearer <token>`，并在业务首帧校验消息类型、大小、权限和会话状态。不要把远端消息直接拼接为控制台命令。

## 7. 外部进程插件协议

Node、Java、Kotlin 进程模块通过 stdin/stdout 使用 UTF-8 NDJSON 协议。stdout 只能输出协议 JSON；普通日志必须写 stderr。

```json
{"type":"log","fields":{"level":"info","message":"started"}}
```

启动时框架会向子进程发送 `init`、`enable`；停止时发送 `disable`、`shutdown`。子进程可注册命令、事件、任务与 Web UI 数据，但不得把未认证的远端请求直接映射为高权限操作。

## 8. 纯服务端回放记录

### 8.1 能做与不能做

Headless 服务端没有图形渲染帧，不能直接输出 MP4。纯服务端应记录：世界快照 `.msav`、事件流 NDJSON、元数据 JSON。之后可由客户端或独立渲染器回放；如需视频，再由渲染器配合 FFmpeg 编码。

### 8.2 推荐目录

```text
config/yzf/data/replays/<session-id>/
  manifest.json
  events.ndjson
  snapshots/
    000000.msav
    000300.msav
```

### 8.3 manifest.json

至少记录 `sessionId`、开始/结束时间、地图、游戏模式、服务端版本、快照间隔、事件格式版本、快照列表与 SHA-256 校验值。

### 8.4 记录实现

建议用 Java 服务端插件实现，因为它可直接调用 `SaveIO.save(Fi)`。所有世界读取和保存必须在服务端主线程执行。

1. `PlayEvent` 或 `WorldLoadEvent` 创建 session。
2. 每 60～300 秒用主线程定时任务调用 `SaveIO.save(snapshotFile)`。
3. 监听 `PlayerJoin`、`PlayerLeave`、`PlayerChatEvent`、`BlockBuildEndEvent`、`ConfigEvent`、`DepositEvent`、`GameOverEvent` 等事件，逐行追加 `events.ndjson`。
4. 每条事件写入 `timestamp`、`tick/wave`、`event`、玩家 UUID/comid、位置和必要载荷。
5. `GameOverEvent` 或停服时保存最终快照、写入 manifest、关闭文件句柄。

### 8.5 示例事件行

```json
{"time":1720000000000,"wave":42,"event":"PlayerJoin","uuid":"...","comid":"10001"}
{"time":1720000005000,"wave":42,"event":"BlockBuildEnd","x":120,"y":64,"block":"duo","breaking":false}
```

### 8.6 对外下载

核心目前没有入站 HTTP 下载接口。需要下载时，应新增一个受 Token、TLS、路径白名单和速率限制保护的 HTTPS API；不要直接开放整个 `config/yzf/data/replays` 目录。
